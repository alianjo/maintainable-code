# Glossary

| Term | Meaning |
|---|---|
| Abstraction | A boundary that exposes relevant behavior while hiding implementation details. |
| Adapter | An implementation that translates one interface or protocol into another. |
| Cohesion | How strongly the responsibilities inside a module belong together. |
| Coupling | How much one component depends on another component's details. |
| Dependency injection | Supplying dependencies from outside an object instead of constructing them internally. |
| Domain | The business concepts, rules, and constraints the software models. |
| Fake | A lightweight working implementation used in tests or development. |
| Invariant | A rule that must remain true for a valid object or operation. |
| Port | An application-facing contract describing an external capability. |
| Refactoring | Changing internal structure without intentionally changing observable behavior. |
| Repository | A persistence boundary that offers domain-oriented storage operations. |
| Side effect | An observable interaction with state outside a function, such as I/O or mutation. |
| Stub | A test object that returns predetermined values. |
| TDD | Test-Driven Development: Red, Green, Refactor. |
